## Why SaaS Consolidation Usually Fails

The CFO mandates a 20% reduction in SaaS spend. The ops team builds a spreadsheet. The spreadsheet becomes a project that runs for six months. At the end, you've cancelled three tools nobody was using anyway and saved $12,000.

That's not consolidation. That's pruning dead weight.

Real consolidation — the kind that generates 30–40% cost reduction while improving capability — requires a different approach. It starts with understanding the actual jobs your software stack is doing, not just cataloguing what you're paying for.

## Step 1: Map Jobs to Tools, Not Tools to Costs

Most consolidation projects start by listing tools and their costs. The problem is that cost is the wrong starting point. The right starting point is function.

For each tool in your stack, answer: **What job is this tool hired to do?**

Not "What does this tool do?" (that's the vendor's description). But "What specific outcome does this team need, and is this tool the right way to produce it?"

When you map jobs to tools rather than tools to costs, you'll typically find:
- **3–5 tools doing the same job** in different departments (classic shadow IT overlap)
- **2–3 tools that were hired for one job but are used for something different**
- **1–2 tools that aren't actually doing any job** (zombie subscriptions)
- **Gaps where no tool exists** but manual work is filling the function

## Step 2: Score Your Stack Before You Consolidate

Before deciding which tools to cut, you need to know which tools are actually good at the job they're doing. A tool you're paying $500/month for might score 8.2/10 on the right evaluation framework. A tool you're paying $2,000/month for might score 4.1/10.

Cutting the expensive one without checking quality is how consolidation projects end up costing you operationally even while saving money.

For each tool in your stack:
- **Current score** — How well does it do the job today?
- **Alternative score** — Is there a better tool available for less money?
- **Switching cost** — What's the real cost (time, risk, training) to migrate?
- **Strategic alignment** — Does this tool align with where the company is going?

## Step 3: Identify Consolidation Candidates

With jobs mapped and tools scored, consolidation candidates emerge naturally. Look for:

### High-Cost, Low-Score Tools
Tools costing significant money but scoring below 6/10 on your evaluation framework are immediate candidates for replacement. The question is: replace with what?

### Overlapping-Job Tools
When two or three tools are doing the same job for different departments, consolidation is the obvious move. The question is: which tool wins, or do you need a new one?

### Good-at-Job But Overpriced Tools
A tool scoring 8/10 but costing 3x the market rate for similar quality is a negotiation or migration opportunity.

### The "Nobody Uses This" Category
Surprisingly often, consolidation audits surface tools that were purchased, onboarded, and then quietly stopped being used. Check login data where available, or ask the department directly.

## Step 4: Build the Consolidation Roadmap

A consolidation roadmap prioritizes initiatives by ROI and migration risk. A simple 2x2 works well:

| | **Low Migration Risk** | **High Migration Risk** |
|---|---|---|
| **High Savings** | Do first | Plan carefully |
| **Low Savings** | Do if easy | Deprioritize |

High-savings, low-risk consolidations are your quick wins: replacing a $1,500/month tool with a $400/month tool that does the same job, where the migration is simple.

High-savings, high-risk consolidations — like replacing your CRM or your core data platform — deserve detailed migration planning before you start cutting.

## Step 5: Execute in Phases, Not All at Once

Consolidation projects that try to do everything simultaneously create operational risk and stakeholder resistance. A phased approach that shows early wins builds momentum:

**Phase 1 (30 days):** Cancel zombie tools. No migration required.

**Phase 2 (60 days):** Execute high-savings, low-risk replacements. Show the ROI.

**Phase 3 (90 days):** Begin migration planning for high-stakes consolidations.

**Phase 4 (ongoing):** Establish a process for evaluating new tools before purchase so the stack doesn't grow back.

## Common Mistakes to Avoid

**Cutting before validating alternatives:** Don't cancel Tool A until you've verified Tool B can actually do the job. Research your replacement options before you pull the contract trigger.

**Ignoring switching costs:** A $200/month tool that requires $20,000 in migration effort isn't actually saving money in year one. Model the full ROI including migration costs.

**Consolidating without team buy-in:** The teams using these tools have opinions. Include them early. Consolidation projects that bypass users often result in shadow IT regrowth within six months.

**Not establishing a prevention process:** Consolidation solves today's sprawl. Without a process for evaluating and approving new tools, you'll be consolidating again in 18 months.

## The Maintenance Layer

After consolidation, the goal is to stay consolidated. That means:
- **A defined evaluation process** for new tools before they're purchased
- **Regular stack audits** (quarterly is often enough)
- **Clear ownership** for who approves software purchases
- **Renewal reviews** that happen proactively, not reactively

## What Good Looks Like

A well-consolidated SaaS stack for a 100-person company typically has:
- 20–35 core tools (not 80+)
- Clear ownership for each tool
- No significant functional overlap between tools
- A defined evaluation process for additions
- Regular renewal reviews with documented rationale

The goal isn't minimalism. It's intentionality — every tool earning its place with clear evidence.
